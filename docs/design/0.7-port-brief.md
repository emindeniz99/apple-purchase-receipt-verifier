# 0.7 port brief

The instructions every port was given when it moved to the 0.7 API. Use it
for a new port, or to re-check an existing one.

## Read first, in this order

1. `docs/design/0.7-api.md`: the API and every owner rule. This is the spec.
2. `docs/design/0.7-hardening-parity.md`: the hardening each port must add.
   Your port's checklist is at the end.
3. `fixtures/cases-0.7.json` and `cases-0.7.schema.json`: the shared cases.
   The top-level `comment` explains the semantics: operations, clock,
   trustedRoots, field JSON pointers including `[key=value]`, lengths, exact
   `toJson`, endpoint `/status`, the `decodeBase64` internal hook,
   `maxMillis`, `messageMustNotContain` and `anyOutcome`.
4. The reference implementations: Java (`java/`, runner
   `ConformanceCasesTest.java`) and Rust (`rust/src`, runner
   `rust/tests/conformance.rs`). When the design is unclear, do what they do.
5. "Behaviours a new port most often gets wrong", below.
6. The repo `CLAUDE.md` and `CONTRIBUTING.md`, and your port's README and CI
   job in `.github/workflows/ci.yml`.

## What to do

- Replace the port's public API with the 0.7 API exactly as the design's
  port table says for your language: result form, clock type, data types,
  64-bit id type, floor.
- Reuse the port's existing, tested crypto, ASN.1 and bounds code. Never
  hand-write RSA, ECDSA or other crypto primitives.
- Add every item on the port's hardening checklist, above all the top-down
  chain walk (#161). No signature is verified and no key is decoded or used
  until a pinned root has vouched for it. Stranger certificates are ignored,
  so a genuine receipt padded with extra certificates still verifies.
- Check order on both paths: strict input and structure; then the chain to
  a pinned root together with certificate validity; then Apple's marker
  OIDs; then the signature. An expired chain that lacks a marker is
  `INVALID_CERTIFICATE`.
- Signer lookup: when several embedded certificates carry the SignerInfo's
  issuer and serial, try each in bag order. One passing is enough;
  otherwise the verdict is the first match's failure.
- Refuse an unknown critical X.509 extension (`UNTRUSTED_CHAIN`), using the
  processed-extension lists in `rust/src/chain.rs`. Refuse duplicate or
  mismatched `contentType`/`messageDigest` signed attributes
  (`INVALID_SIGNATURE`).
- The conformance runner runs every case in `fixtures/cases-0.7.json`,
  enforces `maxMillis` (the second call, after one warm-up) and
  `messageMustNotContain`, accepts any verdict except `INTERNAL_ERROR` for an
  `anyOutcome` case, and fails if any case did not run. Never skip or weaken
  a case.
- Migrate the existing tests to the new API without losing coverage:
  security, bounds, trust isolation, fuzz harness, benchmarks.
- Rewrite the README for 0.7: quick start for the three methods,
  post-verification checklist, device hash example, notifications V2 loop,
  endpoint status table, decode rules, and an "Upgrading from 0.6" table.
  Compile or run the snippets where the toolchain allows.
- Keep the published floor from the design table (PHP moves to 8.2, Ruby to
  3.3). A version constant stays at the last released version with its
  release-please marker; release-please does the bump.

## Commits

- Conventional Commits with the port as scope, as `CONTRIBUTING.md` says.
  The API replacement is `feat(<port>)!:` with a `BREAKING CHANGE:` footer.
- Stage only your port's paths: several ports may share one checkout.
- Lock files: regenerate one only when dependencies change, and only with
  the command in `CONTRIBUTING.md`'s lock-file table. Never edit one by hand.
- Each commit should build and pass its tests where practical.

## Behaviours a new port most often gets wrong

- Receipt attributes keep their encoded order; never sort the SET.
- Unwrap the double OCTET STRING wrapping for in-app values too.
- Attribute fields after the third are tolerated.
- The receipt version must be a well-formed INTEGER.
- Attribute types run from 0 to 2^31-1; a wider type makes the whole payload
  unreadable.
- Bundle id octets always go to `bundleIdBytes`, never to the raw map.
- An in-app purchase that fails as a whole is kept raw under type 17.
- When every signer fails, report the first SignerInfo's failure.
- An unreadable signer certificate is `INVALID_CERTIFICATE`; an unreadable
  stranger is `MALFORMED`; a broken signer outranks a stranger.
- A signer issued straight by the root is `INVALID_CERTIFICATE_PURPOSE`.
- The WWDR marker is checked on the intermediate, `path[1]`.
- `signedDate` must fit a signed 64-bit integer; a float is truncated
  within range, and 2^63 saturates.
- Duplicate JSON members: the last one wins. Duplicate receipt attributes:
  the first one wins.
- JSON depth is 64 including the outer value, number length 1000, name
  length 50000.
