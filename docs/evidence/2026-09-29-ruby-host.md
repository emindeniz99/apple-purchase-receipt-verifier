# The Ruby gem as a wasmtime host

Date: 2026-09-29. Code, scripts and raw results are in
`2026-09-29-ruby-host/`; its `README.md` has the file table and the commands.

**Question.** Does the 0.7 Ruby API keep its shape and its answers when the
gem holds no verification code and runs `aprv.wasm` through the `wasmtime`
gem? This feeds MIGRATION step 5.5. The module is round 13's stand-in
(canonical ABI, 0.6 core, SHA-256 `da786ac8...fdb68`), so the parity gate is
the spike's and the 311 cases wait for the real core (G1).

Labels: TESTED (ran here), EXPECTED (inferred, not run).

Environment: Ubuntu 24.04 x86_64, 4 CPUs shared with five other agents (load
average 8 to 30 during the runs), Ruby 3.3.6 (the only Ruby here), wasmtime
gem 48.0.1 (`x86_64-linux`), minitest 6.0.6, rubocop 1.x and steep 1.10.0 from
`gemfiles/tools.gemfile.lock`, ruzzy 0.8.0 with clang 18.

## Result

- **Corpus parity: as expected (TESTED, `results/classify.txt`).** All 6,179
  rows through the gem's host code: 6,176 byte-identical to the ABI v1 Node
  rows, 2 `clock-moves-chain`, 1 `init-refusal`, 0 traps
  (`results/corpus-runs.txt`). The rows were driven through `Guest` and the
  instance handling the facade uses, per init configuration, discarding an
  instance after a trap.
- **The suite (TESTED).** `rake test`: 393 runs, 29,898 assertions, 221
  failures, 1 skip. The skip is the gem-install round trip, which
  `APRV_PACKAGING=1` runs (below). Every failure is a conformance case; the
  other 80 tests pass against the shipped module. 0.7's suite was 497 runs,
  22,462 assertions, 0 failures, 1 skip.
- **The 221 failures are the 0.6 core (TESTED, `results/standin-differences.txt`).**
  69 verified but in the 0.6 payload wire, which the facade refuses as
  `INTERNAL_ERROR`; 86 refused with a 0.6 reason token that maps onto the
  expected 0.7 reason; 22 `decodeBase64` cases whose base64 rule agrees but
  whose reason token is 0.6's; 42 where the 0.6 core decided differently (its
  size-cap, nesting, marker and signer rules changed in 0.7); 2 endpoint cases
  for 0.7 rules the 0.6 core lacks. Nothing was changed to make any pass.
- **The gem installs without a Rust toolchain (TESTED).** Built gem: 1,025,024
  bytes. Installed into an empty `GEM_HOME` with `cargo` and `rustc` off `PATH`,
  RubyGems picked `wasmtime-48.0.1-x86_64-linux`, the prebuilt native gem
  (109 MB installed in all), and `script/consumer_smoke.rb` verified a genuine
  receipt through the endpoint from an empty directory. The typed payload
  check was skipped (`APRV_SMOKE_STANDIN=1`): it needs the 0.7 wire.
  `APRV_PACKAGING=1 rake test TEST=test/packaging_test.rb` passes 4 of 4.
- **Lint and types (TESTED).** `rubocop`: 41 files, no offenses. `steep check`
  and `rake rbs`: clean.
- **The GVL is released (TESTED, `test/thread_test.rb`).** During a 91 ms
  verification of the 1 MiB byte-floor receipt a thread sleeping 1 ms at a
  time made at least 5 ticks; with `to_func(gvl: true)` it made 0. That is
  the evidence the machine can give while its cores are taken.
- **Thread scaling is not measurable here (TESTED, `results/threads.txt`).**
  With the cores saturated, 1, 2 and 4 threads gave 400 to 430, 250 to 714 and
  375 to 377 G5 receipts per second, and 103 to 109, 119 to 161 and 145 to 154
  JWS per second. The spike, on a quiet machine, measured 716, 1,298 and 2,358
  G5 per second and 232, 410 and 746 JWS ([Ruby][ruby]). The gate wants the
  run repeated on free cores: `ruby -Ilib bench/threads.rb --assert`.
- **Start-up and per call (TESTED, `results/startup.txt`, load 9).**
  `require` 14.5 to 22.8 ms; the first Verifier 5.6 to 6.5 s wall and 5.6 to
  6.8 s of CPU (compiling the module; the spike's 1.22 to 1.35 s was on a quiet
  machine); a later Verifier 0.2 to 0.4 ms; the first call 5 to 9 ms; a G5
  receipt 2.5 to 3.6 ms wall and 2.4 to 2.6 ms CPU per call; the
  shared-sandbox JWS 9.2 to 11.5 ms wall and 8.4 to 10.2 ms CPU. The spike:
  1.33 ms and 4.71 ms.
- **ruzzy compiles and runs (TESTED).** All four targets ran 12 to 20 s under
  ruzzy 0.8.0 with clang 18, 2,182 to 302,667 units each, without a violation.
  Under the stand-in the `verify_receipt` and `verify_transaction` targets
  never see an accepted input, so their anchor-set invariant is unexercised
  until the real module.

## What the facade does

- One compiled module per process; every export called with
  `to_func(gvl: false)`; `random-get` from `SecureRandom`, refused above 1 MiB;
  any import but `random-get` refused at load; the module checked against its
  recorded SHA-256; `Store` limits 256 MiB, one instance, one memory, one
  table.
- One instance per call, from a pool: idle instances in a `Thread::Queue`
  (at most 8 kept), a new one made when none is idle, an instance discarded
  when the call did not return normally, trapped, ran into its memory limit or
  produced an answer the wrapper cannot read.
- The clock is read once per call before the input; a clock that raises or
  answers anything but an Integer in 0 to 2^63-1 is `INTERNAL_ERROR` (21009 at
  the endpoint) whatever the input.
- The hand-rolled canonical-ABI call is about 40 lines (`guest.rb`: `lower`,
  `lift` and `call`), against the spike's 35 in Java.

## Findings

- **wasmtime-rb coerces a Float to an integer where the WIT says `u64`**
  (TESTED, `test/abi_test.rb`). The facade's own check that the clock answered
  an Integer is what keeps a Float from becoming an instant. A generated
  binding would not have caught it either (the same class of gap as finding 2
  of round 13).
- **Bundler re-points a child Ruby.** A subprocess started under `bundle exec`
  with `RUBYOPT` and `GEM_HOME` overridden still sees the bundle's values
  (Ruby restores them at start-up); the packaging test uses
  `Bundler.with_unbundled_env`.
- **`Config.defaults.roots` is empty, and `Config.new(roots: [])` is refused.**
  The first is the module's Apple roots, the second the empty caller set 0.7
  refuses. Anything that read `Config.defaults.roots.size` (the RubyGems smoke
  program and `consumer_smoke.rb` did) has to change.

## The 0.7 suite, test by test

184 tests besides the conformance runner (`results/test-inventory.tsv`): 77
covered by an existing case, 38 port-only behaviours with a proposed case, 35
kept in this lane's suite, 12 sweeps that belong to the corpus, 12 that stay
with the host or the tooling, 10 that died with the hand-written code.

## Limits

- Ruby 3.3.6 on Linux x86_64 only. Ruby 3.4 and 4.0, macOS and musl were not
  run; the CI matrix is in `ruby/CI-NOTES.md`.
- The module is the stand-in. Every parity number holds for it; the 311 cases,
  the typed payload and the anchor-set fuzz invariants wait for the release
  build.
- Timings and thread scaling were taken on a saturated machine.
- A forked server that creates its Verifier before the fork is untested.
