# ABI 0.2.0: a WIT enum for the environment, with a checked lift (2026-11-02)

**Question.** Can `aprv.wasm`'s `env: u32` become a WIT `enum environment
{ production, sandbox }` without an out-of-range discriminant being read
as a wrong environment, and at what size cost? R23 rejected an enum in
2026-09 because wit-bindgen lifted it with an unchecked `transmute`. This
feeds the owner's decision D1 and DECISIONS.md R46.

**Versions.** rustc 1.99.1, wit-bindgen 0.63.0, wasm-tools 1.262.0,
wasi-sdk 34.0 and OpenSSL 4.0.3 as `tools/wasm-toolchain.sh` pins them;
Node 22.22.0 (V8), wazero v1.12.0, Wasmtime 50.0.1 (the ABI tests), Endive
as `java-wasm/pom.xml` pins it. Base commit `04bc1f4` (ABI 0.1.0). Code,
commands and raw output are in `2026-11-02-abi-0.2-enum-lift/`.

## The hazard

wit-bindgen-rust 0.63.0 generates the enum's lift as
`if !cfg!(debug_assertions) { return transmute(val) }`, and panics on an
out-of-range value only with debug assertions on
(`wit-bindgen-rust-0.63.0/src/interface.rs`).

A toy guest with the same profile as `aprv.wasm` (LTO, one codegen unit,
`panic = "abort"`) showed it first (`toy/results.txt`): in release, 2 came
back as `production` and 255 and 2^32-1 as `sandbox`; with
`[profile.<p>.package.spike-enum] debug-assertions = true`, 0 and 1
answered and the other three reached the panic hook (43,089 to 44,817
bytes).

The real module does the same. Built with the enum and no override
(variant `u`), the endpoint given the sandbox G5 receipt answered 21007
(production) for env 2 and 0 (sandbox) for 255 and 2^32-1, as values,
on V8 and on wazero (`real/results.txt`).

## The setting

```toml
[profile.wasm.package.aprv-abi]
debug-assertions = true
```

Cargo takes `debug-assertions` in a package override. The generated
`cfg!` expands inside `aprv-abi`, so the override reaches the generated
glue and nothing else: cargo passes `-C debug-assertions=on -C
overflow-checks=off` to `aprv-abi` alone. With it (variant `a`, the
committed tree), 0 and 1 answer as themselves and 2, 255 and 2^32-1 trap
on every host tried:

| Host | What env 2, 255 and 2^32-1 give |
|---|---|
| Wasmtime 50.0.1 (ABI tests, `CoreGuest`) | `Trap::UnreachableCodeReached` |
| wazero v1.12.0 | `wasm error: unreachable` |
| V8 (Node 22.22.0) | `RuntimeError: unreachable` |
| Endive | `TrapException: Trapped on unreachable instruction` |

The panic goes to std's hook, whose calls into WASI trap in
`wasi-none.c`, and the abort is `unreachable`; that is the trap kind the
hosts' tests and the ABI fuzz oracle already expect. The Rust ABI test
`an_environment_other_than_0_or_1_traps` fails on variant `u` and passes
on `a`, so the existing env-trap tests on every hand-rolled host guard
the setting.

## Size

| Build | `aprv.wasm` bytes | Against `u` |
|---|---|---|
| `base` (ABI 0.1.0) | 2,841,546 | |
| `u` (enum, unchecked) | 2,841,206 | |
| `a` (enum, checked; committed) | 2,846,071 | +4,865 (+0.17%) |
| `h` (`a` plus a panic hook that traps) | 2,846,388 | +5,182 (+0.18%) |

`a` is 4,525 bytes (+0.16%) larger than ABI 0.1.0's module; the guest
also lost its u64 clock check. The hook in `h` installs at run time, so
std's default hook stays linked and the module only grows; `a` keeps the
default hook. The 2026-09-29 spike measured +0.43% for turning debug
assertions on for the guest crate of that round's module, whose
interface also lifted strings ([canonical ABI spike][cabi], caveat 1).

## Reproducibility

`tools/reproduce-wasm.sh`, run on the commit of variant `a` from a fresh
clone in a new directory, rebuilt `aprv.wasm` and the component byte for
byte (`66a2d6a6…353f`, `d9ff42bf…e3da`).

## `now-ms` as an `s64`

On variant `a`, `now-ms` -1, `i64::MIN` and `i64::MAX` are all values:
`verify-receipt` verifies G5 at each (it carries its own creation date),
the endpoint answers 0 at -1 and 21009 at `i64::MIN` and `i64::MAX`, whose
`request_date` Apple's format cannot write, as the core answers natively.

## Where this stops holding

- wit-bindgen 0.63.0 and rustc 1.99.1. A later wit-bindgen could check the
  lift in release, or change the panic path; the env-trap tests would
  show either.
- Cargo's per-package `debug-assertions` override. If a toolchain stopped
  honouring it, the env-trap tests would fail rather than pass silently.
- Only the hosts above were probed for the trap kind. The Python
  (wasmtime-py) and Ruby (`wasmtime` gem) env-trap tests passed on
  variant `a` locally; Swift (WasmKit) and .NET run theirs in CI.
